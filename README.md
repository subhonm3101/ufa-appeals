# ufa-appeals

Интеллектуальная веб-система анализа и приоритизации обращений граждан с прогнозированием нагрузки (город Уфа). Выпускная квалификационная работа.

Система принимает обращения от граждан через публичную страницу и из файлов (CSV/XLSX), определяет категорию, находит дубликаты и объединяет похожие обращения в проблемы (кластеры), рассчитывает приоритет проблем по прозрачным правилам `rules_v1`, находит всплески обращений и прогнозирует нагрузку по городу, категориям и районам.

> Данные в репозитории синтетические. Система демонстрационная и не является внедрённой информационной системой (см. раздел «Ограничения»).

## Возможности

| Раздел | Назначение | Роли |
| --- | --- | --- |
| Обращения | Рабочий список: статусы, исполнители, сроки ответа, фильтры, поиск по тексту и номеру; карточка с историей, комментариями и фотографиями; ручная проверка категории | оператор, аналитик, руководитель, администратор; исполнитель видит только свои |
| Публичная страница `#/public` | Подача обращения с фотографиями без входа, проверка статуса по номеру | все, без входа |
| Личный кабинет `#/account` | Регистрация и вход, свои обращения, дополнение обращения, уведомления | гражданин |
| Ключи API | Выпуск и отзыв ключей для внешних систем | администратор |
| Загрузка файлов | Импорт CSV/XLSX: проверка без записи, отчёт об ошибках по строкам | оператор, администратор |
| Дашборд | Динамика, прогноз с интервалом, аномалии, структура по категориям, отчёт Excel, печать в PDF | аналитик, руководитель, администратор |
| Очередь и карта | Очередь проблем по приоритету, карта Уфы, карточка проблемы с разбором баллов | аналитик, руководитель, администратор |
| Пользователи и журнал | Управление пользователями, журнал действий | администратор |

Колокольчик в шапке показывает уведомления: назначение, смена статуса, срок ответа истекает, просрочено, гражданин дополнил обращение. Гражданин получает уведомления в кабинете о смене статуса и новом ответе.

## Как обрабатывается обращение

1. Гражданин подаёт обращение на странице `#/public` (текст, район, адрес, почта, до трёх фото) и получает номер вида `UFA-2026-000123`.
2. При регистрации автоанализ определяет категорию и срочность. Если уверенность модели ниже 0,7 или текст не похож на типовые обращения, категория не назначается, обращение получает метку «проверить» и попадает в фильтр «Требуют проверки».
3. Оператор принимает обращение (срок ответа 30 календарных дней), подтверждает или меняет категорию, назначает подразделение и исполнителя.
4. Статусы: новое, принято, в работе, ожидает ответа, решено, отклонено. Отклонение требует причины, решение требует текста ответа; закрытое обращение возобновляют только руководитель и администратор.
5. Гражданин проверяет статус по номеру; наружу отдаются только статус, тема, сроки и ответ. Вошедший гражданин видит свои обращения в личном кабинете и может их дополнить.
6. Внешние системы передают обращения через `POST /api/external/appeals` с заголовком `X-API-Key` и своим `external_id` (повтор не создаёт дубль), статус смотрят через `GET /api/external/appeals/{номер}`.

## Состав

- `backend/` — FastAPI, SQLAlchemy, Alembic, тесты (`backend/tests`), служебные скрипты (`backend/scripts`).
- `frontend/` — React, TypeScript, Vite, Recharts, Leaflet.
- `ml/` — эксперименты и обучение: классификация, дубликаты и кластеры, приоритеты, аномалии, прогноз, порог уверенности. Файлы моделей (`ml/models/`) в git не хранятся.
- `data/` — синтетические обращения и результаты разметки.
- `docs/` — архитектура, схема БД (`schema.sql`, `er_diagram.png`), описание данных, результаты экспериментов (`experiments.md`).
- `docker-compose.yml` — база PostgreSQL 16 + PostGIS.

## Запуск

Нужны Docker, Python 3.13 и Node.js 20.

### 1. База данных

```powershell
docker compose up -d
```

База доступна на `127.0.0.1:5433` (пользователь, пароль и база: `appeals`).

### 2. Бэкенд

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt

$env:APPEALS_DATABASE_URL = "postgresql+psycopg://appeals:appeals@127.0.0.1:5433/appeals"
```

Используйте адрес `127.0.0.1`, а не `localhost`: на Windows `localhost` сначала пробуется по IPv6, и соединения с базой подвисают.

Миграции базы выполняются командой `alembic upgrade head` (из папки `backend`).

Создание пользователя (роли: `operator`, `analyst`, `manager`, `admin`, `executor`; граждане регистрируются сами, роль `citizen`), подробности: `python backend\scripts\create_user.py --help`:

```powershell
python backend\scripts\create_user.py --help
```

Запуск сервера:

```powershell
cd backend
python -m uvicorn app.main:app --port 8000
```

Документация API (Swagger): http://127.0.0.1:8000/docs

### 3. Модель категорий

Автоанализ использует обученную модель `ml/models/tfidf_logreg_A_grouped.joblib`. Если файла нет, обращения регистрируются, но все уходят на ручную проверку. Создать модели:

```powershell
python ml\train_tfidf_baseline.py
```

Скрипты в `ml/` используют scikit-learn, pandas, joblib и matplotlib (последний нужен только для графиков).

Путь к модели можно задать переменной `APPEALS_CATEGORY_MODEL`, папку для фотографий — `APPEALS_UPLOAD_DIR` (по умолчанию `backend/uploads`).

### 4. Данные и расчёты

Скрипты в `backend/scripts` выполняются по порядку; параметры каждого смотрите через `--help`:

1. `load_appeals.py` — загрузка обращений из CSV (`data/appeals_synthetic.csv`).
2. `load_clusters.py` — загрузка кластеров (`data/cluster_assignments.csv`).
3. `run_priority.py` — расчёт приоритетов `rules_v1`.
4. `build_aggregates.py` — агрегаты по дням для аномалий и прогноза.
5. `ml/write_anomalies.py`, `ml/write_forecasts.py` — запись найденных аномалий и прогнозов.

Обращения можно загружать и через интерфейс (раздел «Загрузка файлов»).

### 5. Интерфейс

```powershell
cd frontend
npm run dev
```

Откройте http://localhost:5173 (запросы `/api` проксируются на бэкенд). Публичная страница подачи обращений: http://localhost:5173/#/public.
Сборка: `npm run build`.

## Тесты

Тесты с базой используют отдельную БД `appeals_test`:

```powershell
$env:APPEALS_DATABASE_URL = "postgresql+psycopg://appeals:appeals@127.0.0.1:5433/appeals"
$env:APPEALS_TEST_DATABASE_URL = "postgresql+psycopg://appeals:appeals@127.0.0.1:5433/appeals_test"
cd backend
python -m pytest -q tests
```

Без переменной `APPEALS_TEST_DATABASE_URL` тесты с базой пропускаются. Тестовая база должна быть мигрирована (`alembic upgrade head` с `APPEALS_DATABASE_URL`, указывающим на `appeals_test`). Ожидаемый результат: 342 теста пройдено.

Нагрузочная проверка (бэкенд должен работать):

```powershell
$env:CHECK_EMAIL = "admin@example.com"
$env:CHECK_PASSWORD = Read-Host "Пароль"
python backend\scripts\load_check.py
```

На 5242 обращениях и 3509 кластерах время ответа основных запросов 0,02–0,09 с, отчёт Excel строится за 0,3 с; при 10 одновременных пользователях ошибок нет, около 120 запросов в секунду.

## Ограничения

- Данные синтетические; система не проверялась на реальных обращениях. Классификатор обучен на шаблонных текстах и на реальных обращениях будет ошибаться чаще; для расплывчатых текстов есть проверка знакомости и ручная проверка оператором.
- Охват данных — один год; сезонность оценивается по ограниченной истории.
- Выданные токены доступа нельзя отозвать до истечения срока.
- Ограничение частоты запросов к публичному API хранится в памяти процесса.
- Фотографии хранятся на диске сервера и не входят в резервную копию базы.
- Внешний API принимает обращения без фотографий; уведомления гражданину не отправляются на почту.
- Координаты кластеров на карте группируются около центров районов.
- Для реального внедрения нужны настоящие данные, проверка безопасности, правовая оценка, интеграции и пилотная эксплуатация.
