# Журнал выполнения работы

Проект: интеллектуальная веб-система анализа и приоритизации обращений граждан с прогнозированием нагрузки (г. Уфа).

Каждый шаг фиксируется отдельным коммитом с сообщением «Шаг X.Y: …». Найти коммит шага: `git log --grep "Шаг 9.1"`.

## Этап 9. Рабочий процесс обработки обращений

| Шаг | Содержание | Статус |
| --- | --- | --- |
| 9.1 | Модель данных: статусы и история, подразделения, исполнители, комментарии, публичный номер (миграция 0007) | выполнено |
| 9.2 | API обращения: карточка, смена статуса по правилам переходов, назначение, комментарии; роль «исполнитель» | выполнено |
| 9.3 | API рабочего списка: фильтры, счётчики по статусам, «только мои», просрочки, поиск по номеру | выполнено |
| 9.4 | Интерфейс: список со статусами и карточка обращения (статус, назначение, комментарии, история) | выполнено |
| 9.5 | Уведомления (назначение, смена статуса, срок истекает, просрочено): миграция 0008, API, колокольчик в интерфейсе | выполнено |

Правила: срок ответа 30 календарных дней от регистрации; отклонение требует причины, решение требует текста ответа; закрытое обращение возобновляют только руководитель и администратор; исполнитель видит и меняет только назначенные ему обращения.

## Измеренные показатели

- Автотесты: 232 пройдено (на 7 ноября 2026).
- Нагрузка (5242 обращения, 3509 кластеров): запросы 0,02–0,09 с, отчёт Excel 0,3 с; 10 одновременных пользователей без ошибок, около 120 запросов в секунду.
- Прогноз по городу на неделю: ошибка WAPE 10,4%, интервал 80% накрыл 78,4% фактов.
- Поиск аномалий по новым кластерам даёт примерно в 3,4 раза меньше ложных тревог, чем по числу обращений.

## Известные ограничения

- Данные синтетические, охват один год.
- Токены доступа нельзя отозвать до истечения срока (устранить на этапе 12).
- Координаты кластеров на карте группируются около центров районов.
- Прогноз по категориям не лучше простого среднего за 4 недели.
